# السجل المصاحب الإلكتروني (Electronic Companion Record)

نموذج عملي (MVP) قابل للتشغيل فورًا لتطبيق إدارة الفصل الدراسي وتقييم الطلاب، بواجهة عربية كاملة (RTL)، مبني بـ **React + Vite** للواجهة و **Node.js + Express + SQLite** للخادم.

## أهم الميزات
- إدارة صفوف كاملة: إنشاء، تعديل، أرشفة، **استعادة من الأرشيف**، أو حذف نهائي.
- **مخططات فئات درجات جاهزة (Schemes)**: احفظ توزيع فئات أي صف كمخطط وطبّقه على صفوف أخرى دون إعادة الإنشاء.
- **جدول درجات كامل (Spreadsheet)**: كل الطلاب × كل التقييمات في شاشة واحدة، بتلوين حسب الفئة، مع إضافة تقييمات وملاحظات مباشرة، وتصدير CSV/PDF.
- **توصيات تلقائية حسب الدرجة النهائية**: عبارة وصفية تُختار تلقائيًا بناءً على درجة الطالب النهائية (قابلة للتخصيص من الإعدادات).
- **بنك عبارات وصفية جاهزة** (من الإعدادات) يمكن إدراجها بسرعة عند التقييم.
- سلوك وحضور بأيقونات مميزة، مع **نافذة تفاصيل موحّدة لكل طالب** (درجات + سلوك + حضور) قابلة للفتح من أي تبويب.
- تقارير مفصّلة برسوم بيانية (Bar / Line / Pie) لكل صف أو لكل طالب على حدة.
- صور اختيارية للطلاب (بأفاتار افتراضي تلقائي عند عدم الرفع).
- **اشتراك مدفوع يدويًا**: أسعار بالريال العماني (4 / 7 / 18)، مع تعليمات تحويل ورفع وصل (يظهر للمسؤول كصورة قابلة للتكبير)، ولوحة تحكم خاصة لمالك التطبيق (`/admin`) لمراجعة الطلبات وتفعيل الحسابات.
- **محادثة فورية (Real-time Chat)** بين المعلم ولوحة تحكم المسؤول عبر Socket.IO — أداة دردشة عائمة لدى المعلم، ولوحة محادثات متعددة لدى المسؤول.

راجع `docs/ARCHITECTURE.md` للمواصفات الهندسية الكاملة (Tech Stack، User Flow، ERD).

## التشغيل في VSCode

يحتاج المشروع إلى تشغيل **طرفيتين (Terminals)** في نفس الوقت: واحدة للخادم وواحدة للواجهة.

### 1) تشغيل الخادم (Backend)

```bash
cd backend
npm install
cp .env.example .env
npm run dev
```

سيعمل على: `http://localhost:4000`
(يتم إنشاء قاعدة بيانات SQLite تلقائيًا في `backend/data/educore.sqlite` عند أول تشغيل — لا حاجة لأي إعداد إضافي)

### 2) تشغيل الواجهة (Frontend)

في طرفية ثانية:

```bash
cd frontend
npm install
npm run dev
```

سيعمل على: `http://localhost:5173` — افتح هذا الرابط في المتصفح.

> ملاحظة: طلبات `/api` من الواجهة تُمرَّر تلقائيًا إلى الخادم عبر إعداد الـ proxy في `vite.config.js`، لذا لا حاجة لتغيير أي رابط.

### 3) أول استخدام

1. افتح `http://localhost:5173` → اضغط "أنشئ حسابًا مجانًا"
2. سجّل بياناتك (يبدأ تلقائيًا اشتراك تجريبي 14 يوم بكل الميزات)
3. من لوحة التحكم: "+ إنشاء صف جديد"
4. داخل الصف: أضف طلابًا يدويًا أو استورد ملف CSV (يوجد زر "تنزيل قالب CSV" جاهز)
5. جرّب التبويبات: دفتر الدرجات (Quick-Grid) → السلوك (نقرة واحدة) → الحضور → التحليلات → التقارير

## لوحة تحكم المسؤول (خاصة بمالك التطبيق)

مسار منفصل تمامًا عن حسابات المعلمين، لا يظهر رابطه في أي مكان بالواجهة:

- الرابط: `http://localhost:5173/admin/login`
- كلمة المرور الافتراضية: القيمة الموجودة في `backend/.env` تحت `ADMIN_PASSWORD` (**غيّرها فورًا قبل أي استخدام حقيقي**)
- من هنا تُراجع طلبات تفعيل الاشتراك (وصل التحويل، رقم/مرجع العملية) وتُفعّل أو ترفض كل طلب يدويًا.

رقم التحويل الظاهر للمعلمين معرّف في `backend/src/routes/auth.js` ضمن `PAYMENT_PHONE`، وأسعار الباقات (OMR) ضمن `PLAN_PRICES_OMR` في نفس الملف — عدّلهما مباشرة إذا احتجت تحديثهما.

## المحادثة الفورية (Chat)

- تعمل عبر Socket.IO مباشرة على نفس منفذ الخادم (`4000`)؛ لا حاجة لإعداد إضافي محليًا.
- المعلم: زر دردشة عائم أسفل يسار كل صفحة بعد تسجيل الدخول.
- المسؤول: تبويب "الدردشة مع المعلمين" داخل `/admin` — قائمة محادثات مع عداد غير مقروء، ويمكن بدء محادثة جديدة مع أي معلم من تبويب "كل المعلمين" عبر زر "مراسلة".
- في حال نشر المشروع على نطاقات مختلفة للواجهة والخادم، عدّل `SOCKET_URL` في `frontend/src/api/socket.js` ليطابق رابط الخادم الفعلي.

## ملاحظات
- `better-sqlite3` يحتوي كود C++ يُبنى تلقائيًا عند `npm install`؛ إذا واجهت خطأ بناء على نظامك، تأكد من توفر أدوات البناء الأساسية (على macOS: Xcode Command Line Tools، على Windows: `npm install --global windows-build-tools` أو استخدام WSL).
- لتغيير منفذ الخادم أو مفتاح JWT أو كلمة مرور المسؤول، عدّل `backend/.env`.
- صور الطلاب ووصولات التحويل تُخزَّن كنص base64 داخل SQLite لتبسيط النموذج التجريبي؛ في الإنتاج الفعلي انقلها إلى تخزين ملفات مثل S3/R2 (راجع `docs/ARCHITECTURE.md`).
- هذا المشروع MVP للتجربة والعرض؛ راجع قسم "خطوات موصى بها للانتقال إلى الإنتاج" في `docs/ARCHITECTURE.md` قبل الإطلاق الفعلي.

## الحفظ المحلي لبيانات المعلم

تحتفظ الواجهة الآن ببيانات الملف الشخصي للمعلم داخل تخزين المتصفح المحلي، كما تحفظ نسخة مؤقتة محدودة من استجابات القراءة الأساسية مثل بيانات الجلسة والصفوف وبيانات الصف. عند انقطاع الخادم، تُعرض آخر نسخة محفوظة بدل شاشة فارغة، ويظهر شريط يوضح أن التطبيق يعمل بالنسخة المحلية. عند عودة الاتصال تُستعاد الجلسة، وتُرسل تغييرات الملف الشخصي المؤجلة تلقائيًا إلى الخادم.

من صفحة **الإعدادات ← نسخة احتياطية** يمكن للمعلم رؤية حجم النسخ المحلية ومسحها من الجهاز الحالي. مسح النسخ المحلية لا يحذف البيانات الموجودة في الخادم. أما النسخة الاحتياطية القابلة للتنزيل فتظل هي الخيار الصحيح للنقل بين الأجهزة أو الاستعادة الكاملة.

> التخزين المحلي غير مشفّر بطبيعته، لذلك لا يُنصح باستخدام خيار تذكّر الجلسة على جهاز مشترك أو غير موثوق. لا تُحفظ كلمة المرور داخل التخزين المحلي.


## النسخة المحلية الخفيفة والمزامنة

أصبحت الواجهة تعمل بنمط **local-first**. بعد تسجيل الدخول تُحمّل بيانات المعلم المملوكة له في snapshot واحد عبر `GET /api/sync/snapshot` وتُحفظ في **IndexedDB** داخل المتصفح، مع الاحتفاظ بتوافق خلفي مع localStorage لبيانات الجلسة والملف الشخصي. الصفوف والطلاب والدرجات والسلوك والحضور والتحليلات والتقارير تُعرض من النسخة المحلية فورًا، بينما تتم إعادة التحقق من الخادم في الخلفية.

عمليات الكتابة الأساسية تُطبّق محليًا أولًا ثم تُرسل إلى الخادم. إذا انقطع الاتصال تُحفظ العملية في outbox محلي، وتُرسل بالتتابع عند عودة الاتصال. يدعم المعلم المزامنة عند الطلب أو يوميًا أو أسبوعيًا أو شهريًا من صفحة الإعدادات، وتعمل المزامنة التلقائية أثناء بقاء التطبيق مفتوحًا، إضافة إلى المزامنة عند فتح التطبيق وعودة الشبكة. لا يمكن للمتصفح تنفيذ مهمة مضمونة وهو مغلق على خدمة Render المجانية النائمة؛ لهذا يجب استخدام عامل خادم دائم إذا كانت المزامنة مطلوبة في وقت محدد حتى دون فتح التطبيق.

تم تحسين التقارير من استعلامات متداخلة لكل طالب وتقييم إلى استعلامات مجمعة، كما تم إصلاح الدردشة باستخدام `client_message_id` ومعالجة idempotent لمنع تكرار الرسائل بين HTTP وSocket.IO. وتم تقسيم تبويبات الصف إلى حزم lazy-loaded حتى لا تُحمّل الرسوم البيانية إلا عند فتح التحليلات أو التقارير.

### التشغيل المحلي

```bash
cd frontend && npm ci && npm run build
cd ../backend && npm ci && npm start
```

في PowerShell القديم استخدم الفاصلة المنقوطة بدل `&&`، أو نفّذ الأوامر سطرًا بعد سطر.

### متغيرات الإنتاج

يجب ضبط `LIBSQL_URL` و`LIBSQL_AUTH_TOKEN` و`JWT_SECRET` و`ADMIN_PASSWORD` في إعدادات خدمة الإنتاج، وعدم رفع ملفات `.env` أو الأسرار إلى GitHub. يجب أن يشير `VITE_SOCKET_URL` إلى نطاق الخدمة المنشورة، أو سيستخدم التطبيق نطاق الصفحة تلقائيًا في بيئة الإنتاج.
